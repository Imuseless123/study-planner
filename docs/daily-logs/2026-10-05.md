### 2.2. API Client với interceptor

**Tính năng chính:**
- Request interceptor: tự gắn `Authorization: Bearer <token>` vào mọi request
- Response interceptor: bắt lỗi 401, tự động clear auth + redirect về `/login`
- Helper `getErrorMessage()` để hiển thị lỗi Pydantic/HTTP thân thiện

**Lưu ý bảo mật:**
- Token **KHÔNG** persist vào localStorage (tránh XSS)
- Token chỉ giữ trong memory
- Refresh token (nếu có) sẽ dùng HTTP-only cookie
- User + consent state được persist để tránh F5 mất UX

### 2.3. Auth Store (Zustand)

**State:**
```typescript
{
  token: string | null
  user: UserMe | null
  consentSigned: boolean
  hydrated: boolean
}
```

**Actions:**
- `setAuth(token, user)` — sau login
- `setConsent(signed)` — sau khi ký/rút consent
- `clearAuth()` — sau logout hoặc token hết hạn

**Persist strategy:**
- Persist `user` + `consentSigned` (để F5 không mất UX)
- KHÔNG persist `token` (bảo mật)

### 2.4. Protected Route

Logic 3 lớp:
1. **Chưa login** (no token) → redirect `/login`
2. **Đã login, chưa consent** → redirect `/consent`
3. **Đã login + consent** → cho phép truy cập

Có cơ chế **re-verify** khi F5:
- Nếu có token nhưng chưa có user → gọi `/api/auth/me` để load lại
- Nếu có token + `requireConsent` → gọi `/api/consent` để verify

## 3. Bug phát hiện và fix

### 🐛 Bug 1: "Not authenticated" khi login

**Triệu chứng:**
User đăng nhập bằng `bob/password123` nhưng hiện thông báo **"Not authenticated"** thay vì vào dashboard.

**Nguyên nhân:**
Race condition trong `LoginPage.tsx`:

```typescript
const res = await authApi.login(values);   // 1. Lấy token
const user = await authApi.me();           // 2. Gọi /me NGAY
setAuth(res.token, user);                  // 3. Lưu token SAU
```

→ Bước 2 chạy trước Bước 3 → token chưa có trong store → axios interceptor **không gắn Authorization header** → backend trả **403 "Not authenticated"**.

**Fix:**
1. Thêm parameter `tokenOverride` cho `authApi.me()` và `authApi.getConsent()`
2. Trong `LoginPage`, set token vào store **NGAY** sau login, trước khi gọi `/me`:
   ```typescript
   const res = await authApi.login(values);
   useAuthStore.setState({ token: res.token });  // set sớm
   const [user, consent] = await Promise.all([
     authApi.me(res.token),       // dùng override
     authApi.getConsent(res.token),
   ]);
   setAuth(res.token, user);
   ```

**Bài học:** Trong React, thứ tự side-effect quan trọng. Khi có phụ thuộc giữa các API call, nên truyền token trực tiếp thay vì trông cậy vào store update async.

### 🐛 Bug 2: Nhầm status code 403 vs 401

**Triệu chứng:**
Test không có token → nhận **403** thay vì **401**.

**Nguyên nhân:**
FastAPI `HTTPBearer` mặc định trả 403 khi thiếu header, theo chuẩn OAuth2 phải là 401.

**Quyết định:** Giữ nguyên 403 (không phải bug nghiêm trọng). Nếu cần chuẩn, có thể custom scheme `HTTPBearer401` sau.

## 6. Bài học kinh nghiệm

### 6.1. Về React + async

- **Không trông cậy vào store update async.** Khi có chain API, truyền giá trị trực tiếp thay vì đọc từ store.
- **Race condition xuất hiện khi state update không đồng bộ với render.**
- **Dùng `Promise.all()`** để chạy song song các call độc lập (như `/me` và `/consent`), cải thiện UX.

### 6.2. Về Axios interceptor

- Request interceptor đọc token từ store **mỗi lần request** → không cache token cũ.
- Response interceptor bắt 401 cho toàn bộ app → không cần handle ở từng component.
- Cần **exclude** endpoint `/auth/login` và `/auth/register` khỏi auto-logout (vì đó là các request chưa có token).

### 6.3. Về Ant Design

- Dùng `<AntdApp>` wrapper để có `message` API hoạt động đúng trong React 18.
- `ConfigProvider` với `locale={viVN}` để format ngày/tuần theo tiếng Việt.
- Form validation qua `rules` rất mạnh, không cần tự viết validator.

### 6.4. Về Docker Compose

- Volume `/app/node_modules` cần khai báo riêng để Docker không mount đè node_modules của container.
- `docker compose restart` chỉ restart container hiện có; nếu chưa tạo → dùng `up -d`.
- Khi code frontend đổi, Vite hot-reload tự động, không cần restart container.

### 6.5. Về security

- **Token trong memory** (không localStorage) → giảm rủi ro XSS.
- **Persist user state** nhưng không persist token → F5 mất session nhưng không mất UX (sẽ có refresh flow sau).
- **Bcrypt cost 12** ở backend được verify qua SQL query.
