### 2.2. Backend — Router

**`GET /api/user/data`:**
- Load toàn bộ records của user: subjects, assignments, study_sessions, sleep_logs, mood_logs, schedules, feedbacks, consents
- Build stats tổng hợp: total sessions, total hours, avg sleep, avg focus...

**`DELETE /api/user/data`:**
- **2 lớp bảo vệ:**
  1. `confirm=true` bắt buộc
  2. `username_confirmation` phải khớp chính xác username hiện tại
- Audit log (anonymized) trước khi xóa
- Dùng CASCADE của DB để xóa hết records liên quan
- Return `deleted_at` timestamp

## 3. Điểm kỹ thuật đáng chú ý

### 3.1. 2 lớp xác nhận khi xóa

Thay vì chỉ 1 checkbox (dễ tick nhầm), yêu cầu user **gõ chính xác username**:
- Chống xóa vô ý
- Buộc user conscious về hành động
- Best practice của GitHub, Shopify, v.v.

```typescript
const canDelete =
  confirmChecked && usernameInput === user?.username && !deleting;
```

### 3.2. Export dùng Blob + ObjectURL

```typescript
const blob = new Blob([JSON.stringify(data, null, 2)], { type: 'application/json' });
const url = URL.createObjectURL(blob);
const a = document.createElement('a');
a.href = url;
a.download = `...json`;
a.click();
URL.revokeObjectURL(url);  // Cleanup
```

Ưu điểm: không cần backend route riêng cho download, giữ logic ở FE.

### 3.3. Audit log anonymized

Trước khi xóa, log:
```
[AUDIT] User bob (id=xxx) deleted their account at ...
```

- **Có:** username + user_id + timestamp (cho mục đích audit)
- **Không:** email, password, hay data cá nhân nào khác

### 3.4. CASCADE delete

Backend chỉ cần `db.delete(user)` — DB tự cascade xóa:
- consents, subjects → assignments, study_sessions
- sleep_logs, mood_logs, schedules → feedback

Đã verify ở tầng migration với `ondelete="CASCADE"`.

### 3.5. Schema versioning

Response export có `schema_version: "1.0"`. Khi schema thay đổi (thêm bảng, đổi field), tăng version để client biết format. Best practice cho API contracts.

### 3.6. Export có stats

Ngoài raw data, response có phần `stats` tổng hợp:
- Cho user thấy "bạn đã học X giờ, ngủ TB Y giờ..."
- Có thể dùng để tạo "year in review" sau này
- Tăng giá trị của file export

## 5. Bài học kinh nghiệm

### 5.1. Về UX cho destructive actions

- **2 lớp confirm** (checkbox + gõ text) giảm rủi ro xóa nhầm
- **Preview những gì sẽ bị xóa** — liệt kê cụ thể
- **Màu đỏ + icon cảnh báo** để user không bỏ qua
- **Không cho phép hoàn tác** — nhưng cho user thấy rõ

### 5.2. Về data ethics

- **Right to access** → export JSON
- **Right to erasure** → delete account
- **Informed consent** → hiển thị status consent rõ ràng
- **Right to withdraw** → nút rút lui riêng biệt

### 5.3. Về file download

- Blob + ObjectURL là cách chuẩn cho client-side download
- **Filename có timestamp** để tránh trùng khi user export nhiều lần
- **Pretty print JSON** (`JSON.stringify(data, null, 2)`) để user đọc được

### 5.4. Về audit logging

- Log những gì cần thiết cho compliance (user_id, action, timestamp)
- **Không log** PII (email, password, data)
- Trong production: nên đẩy vào log aggregation service (Sentry, Datadog...)
