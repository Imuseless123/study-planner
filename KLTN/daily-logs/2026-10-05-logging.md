## 1. Mục tiêu

Sau khi hoàn thành Authentication + Consent, tiếp tục triển khai feature **Logging** — 3 chức năng tiếp theo trong 14 FR:

- **FR #3:** Log study sessions (subject, duration, focus)
- **FR #4:** Log sleep (bedtime, wake time, quality)
- **FR #5:** Log mood (energy, stress)

**Điều kiện tiên quyết:**
- Backend đã có 3 POST endpoints (`/api/log/study`, `/api/log/sleep`, `/api/log/mood`)
- **Thiếu:** GET endpoints để list history + DELETE để xóa log

**Nguyên tắc:** User phải có khả năng xem lại lịch sử + xóa log sai, không chỉ ghi mới.

Ngoài 3 POST đã có, thêm 6 endpoints (3 GET + 3 DELETE):

| `DELETE` | `/api/log/sleep/{sleep_id}` | Xóa sleep log |

## 4. Điểm kỹ thuật đáng chú ý

### 4.1. Sleep time logic

Vấn đề: User nhập giờ đi ngủ 23:00 và giờ thức 07:00. Backend có CHECK constraint `wake_time > sleep_time`.

**Giải pháp:** Ở frontend, khi combine date + time:
```typescript
let wakeAt = sleepDate.hour(wakeTime.hour()).minute(wakeTime.minute());
if (wakeAt.isBefore(sleepAt) || wakeAt.isSame(sleepAt)) {
  wakeAt = wakeAt.add(1, 'day');
}
```

→ Tránh được lỗi 422 từ backend mà không cần user phải hiểu logic.

### 4.2. Upsert mood

Mood log là **1 record / user / ngày** (unique constraint `uq_mood_user_date`). Nếu user ghi lần 2 cùng ngày → backend **update** thay vì insert.

**Repository:**
```python
existing = db.query(MoodLog).filter(
    MoodLog.user_id == user_id,
    MoodLog.log_date == log_date
).first()
if existing:
    existing.energy_level = energy
    existing.stress_level = stress
    # update thay vì insert
```

### 4.3. Ownership check ở DELETE

Mọi DELETE endpoint đều verify user sở hữu record:
```python
s = db.query(StudySession).filter(
    StudySession.session_id == session_id,
    StudySession.user_id == user_id,  # ← Bắt buộc
).first()
if not s:
    return False  # 404
```

→ User A không thể xóa log của User B ngay cả khi biết `session_id`.

## 6. Bài học kinh nghiệm

### 6.1. Về UX

- **Form + List side-by-side** giúp user thấy ngay kết quả sau khi submit
- **Auto-refresh** sau submit giảm ma sát, không cần F5
- **Smart defaults** (VD: ngày hôm nay, focus = 3) giúp ghi log nhanh hơn
- **Popconfirm** tránh xóa nhầm

### 6.2. Về backend API design

- RESTful: `POST` để tạo, `GET` để list, `DELETE` để xóa — tách biệt rõ ràng
- List response có `{items: [...], total: N}` thay vì chỉ array — dễ mở rộng sau này (pagination)
- Derived fields (như `hours`) nên tính ở **backend** để đảm bảo consistency
- Validate input ở cả Pydantic (backend) và Form rules (frontend)

### 6.3. Về frontend state management

- 3 tabs độc lập về data nhưng share `subjects` state
- Dùng `Promise.all()` để load song song 4 API call → giảm thời gian load
- `useCallback` cho `refreshAll` để tránh infinite loop trong `useEffect`

### 6.4. Về database query

- `JOIN` với `subjects` trong `list_study_sessions` để lấy `subject_name` — tránh N+1 query ở frontend
- `func.date()` để group theo ngày từ `timestamp`
- `group_by` nhiều columns cho heatmap matrix

### 6.5. Về timezone

- Backend lưu `TIMESTAMPTZ` (UTC)
- Frontend dùng `dayjs` để format khi hiển thị
- Khi gửi lên: `toISOString()` để convert local → UTC
- **Lưu ý:** Nếu sau này deploy production, cần verify timezone handling khi server ở múi giờ khác
